# Decisiones del dialecto

Estas son decisiones del equipo para puntos no fijados por el enunciado. No se atribuyen al enunciado como requisitos.

* Palabras clave e identificadores sin distinción de mayúsculas; nombres ASCII `[a-z_][a-z_0-9]*` normalizados a minúsculas. No se admiten identificadores entre comillas. Cadenas Unicode entre comillas simples, escape `''`, sin saltos de línea. Comparaciones de cadenas sensibles a mayúsculas, por orden Unicode.
* Scripts vacíos permitidos; sentencias separadas por `;`, terminador final opcional. Un error léxico/sintáctico rechaza todo el script antes de ejecutar. Después, cada sentencia se valida y se aplica por separado; al primer error se detiene y las anteriores permanecen. No hay comandos de transacción.
* INT usa enteros Python limitados a 4096 dígitos decimales de magnitud, tanto en literales como en resultados calculados; ese límite mantiene serialización JSON y diagnósticos seguros. FLOAT usa IEEE-754 finito y rechaza desbordamientos, también en agregados. No se convierte BOOLEAN a número. Solo se permite conversión implícita INT → FLOAT. No se convierte texto a fecha ni a número. Literales de fecha `DATE 'YYYY-MM-DD'`, validados con calendario gregoriano; no hay aritmética de fechas. VARCHAR cuenta caracteres Unicode y exige n positivo.
* Las columnas admiten NULL salvo NOT NULL o PRIMARY KEY. Los valores omitidos en INSERT son NULL; no hay DEFAULT. UNIQUE permite varios NULL y PRIMARY KEY implica unicidad y no nulidad. Las claves son simples; no hay CHECK.
* Ampliación solicitada por el profesor el 4 de noviembre: llaves foráneas de una columna mediante REFERENCES en columna, FOREIGN KEY en tabla y ALTER TABLE ADD FOREIGN KEY. La referencia debe apuntar a PRIMARY KEY/UNIQUE con igual tipo y tamaño VARCHAR. NULL no exige padre salvo NOT NULL. La política es restrictiva: no permite DROP del padre mientras exista una tabla hija que lo referencia, aunque esté vacía; no permite INSERT/UPDATE/DELETE que dejen referencias huérfanas. Se comprueba el estado final de cada sentencia, incluidas referencias a sí misma. No hay CASCADE, claves compuestas, nombres de restricciones ni DROP CONSTRAINT; las tablas en ciclo no pueden eliminarse individualmente mientras exista el ciclo de esquema.
* NULL usa lógica ternaria. Comparaciones con NULL producen desconocido; WHERE, ON y HAVING solo aceptan verdadero. IN/NOT IN contempla NULL y conjuntos vacíos. COUNT(*) cuenta filas, COUNT(expr) ignora NULL; SUM/AVG/MIN/MAX ignoran NULL y retornan NULL en entrada vacía. COUNT retorna 0.
* INNER JOIN con ON; no uniones implícitas ni exteriores. Todas las consultas SELECT requieren FROM. Alias de tabla reemplaza el nombre original en el ámbito. Columnas sin calificar deben identificar exactamente una tabla en el ámbito más próximo.
* Proyecciones agregadas solo admiten expresiones agrupadas o expresiones construidas con ellas. HAVING requiere agrupación o agregación. ORDER BY admite expresiones y alias de proyección únicos; ASC predeterminado. NULL va al final en ASC y al principio en DESC; empates conservan el orden de lectura, sin garantía de orden SQL si no hay ORDER BY.
* Subconsultas exclusivamente en WHERE, incluidas las de consultas anidadas. Pueden correlacionarse con ámbitos exteriores; el ámbito interior oculta alias exteriores del mismo nombre. IN y subconsultas escalares exigen una columna. Una escalar con cero filas produce NULL; más de una fila causa error. Con almacenamiento disponible se prevalidan las cardinalidades antes de aplicar cada sentencia, y se conservan las comprobaciones al evaluar. El análisis sin almacenamiento solo puede validar estructura y tipos; después de la primera modificación de un script analizado no anticipa el estado de sus datos. EXISTS no exige cardinalidad específica. Se rechazan subconsultas en proyección, GROUP BY, HAVING, ORDER BY y asignaciones. No se admiten tablas derivadas en FROM, UNION, DISTINCT, LIMIT ni funciones ajenas al subconjunto.
* Índices simples y no únicos sobre cualquier tipo admitido. Igualdad, desigualdad `<> !=` y rangos `< <= > >=` entre columna y literal (incluido signo), en cualquier orden, son compatibles. También se indexan IN/NOT IN no correlacionados y comparaciones contra escalares independientes. AND utiliza un índice y evalúa el resto como filtro; OR une candidatos si ambos lados tienen acceso indexado completo. Los filtros WHERE de JOIN también se aplican a candidatos indexados de cada tabla compatible. Las subconsultas no correlacionadas se reutilizan dentro de una sentencia. Las correlacionadas, funciones y expresiones de columna conservan su evaluación general; ON no utiliza una estrategia de unión indexada. Los índices no alteran resultados.
* El proyecto es educativo: un solo escritor a la vez por directorio; no ejecutar CLI y GUI escribiendo simultáneamente. Cada cambio publica metadatos de una generación y solo las filas modificadas; comparte archivos inmutables de generaciones anteriores y actualiza los índices afectados. Los metadatos y cada índice afectado se escriben completos. Las generaciones referenciadas deben conservarse; no hay compactación automática ni garantías de recuperación ante pérdida eléctrica del sistema. Sí hay publicación atómica frente a fallos de validación o de escritura previos al manifiesto.
